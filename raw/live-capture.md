## 背景

2026 年 4 月 20-23 日，香港有 Web3 Festival。  
我原本想去现场，但票价超预算：1 天 199 美元、2 天 299 美元、4 天 699 美元。  
学生票虽然免费，但我的学生身份也刚过期，只能转线上看直播。

问题在于：直播信息密度太高，长时间盯着看效率很低。  
我的目标是把“看直播”改造成“先录制 -> 再转写 -> 再让 AI 总结 -> 我只看重点”。

## 核心难点

第一步不是总结，而是**稳定拿到直播流并录下来**。  
我一开始以为需要抓包、证书、代理，门槛很高。

## 解决思路（来自社区）

搜索关键词：`微信直播`、`直播录屏`。  
最终找到一个很实用的方案：通过 DLNA 投屏协议截获直播流地址（来源：[知乎讨论](https://www.zhihu.com/question/516206579)）。

关键原理：

- 微信视频号投屏使用标准 DLNA 协议
- 电脑伪装成电视设备后，投屏时会拿到真实 `m3u8` 地址
- 不需要抓包、装证书或代理

相关工具：

- `wechat-finder-dlna`
- 项目地址：`github.com/gtoxlili/wechat-finder-dlna`

基本用法（示意）：

```bash
pip install wechat-finder-dlna

# 获取直播流地址
wechat-finder-dlna

# 直接录制为 MP4（示例）
wechat-finder-dlna --record live.mp4 --duration 01:00:00
```

## 我做的产品化改造

拿到方案后，我用 Xcode 做了一个 macOS 小工具，把录制流程产品化：

### 1) 录制任务创建

- 输入直播流 URL
- 选择保存目录
- 设置文件名前缀
- 设置最长录制时长
- 可选：启用 `caffeinate` 保持 Mac 唤醒
- 点击 `Add Recording` 后，调用本机 `ffmpeg` 开始录制

### 2) 多任务管理

每个任务用卡片展示，可同时管理多个录制任务。单卡信息包括：

- 当前状态
- PID
- 保存路径
- 已写入大小
- 录制时长
- 处理速度
- 实时日志
- 上次刷新时间

### 3) 生命周期控制

每个任务支持：

- Refresh
- Pause
- Resume
- Stop
- Kill

### 4) 外部进程接管

支持通过 PID 附加到外部已运行的 `ffmpeg` 任务，实现可视化监控与控制。  
系统会尽量识别输出文件、轮询状态，并允许发送暂停/恢复/停止/强杀信号。

### 5) 持久化恢复

- 退出 app 后任务列表不会清空
- 重启后可恢复上次记录
- 若 PID 仍存活，尽量继续接管监控
- 已结束任务保留，直到手动清理

## 当前效果

- 全程后台运行，资源占用低
- 录制稳定性和视频质量都不错
