## 背景（保留原话感觉）

2026 年 4 月 20-23 号香港 Web3 Festival。
本来想去现场，官网票价：一天 199 美元，两天 299，四天 699。直接拜拜。
学生票免费，但学生卡一月份到期了。只能改看线上直播。

问题不是内容，是我盯不住。上学时三小时课，注意力大概只有三十多分钟。直播更长、更密、多会场并行。

目标：录下来 -> 转写 -> AI 总结/问答。人只处理关键问题。
卡住的是第一公里：视频从哪来。

## 弯路

一开始以为要爬虫、抓包、装证书、挂代理。不会，问 AI 也是 mitmproxy 这类劝退方案。活动只有四天，不能跟协议死磕。

搜关键词：微信直播、直播录屏。

否掉的方案：
- 屏幕录制：文件大、风扇转、通知和消息音会进视频
- 现成下载器：直播 HLS 地址会过期，没有稳定公开接口
- Charles/抓包：长连接重连后地址变，不能丢后台

## 真正能用的办法

知乎：https://www.zhihu.com/question/516206579
工具：https://github.com/gtoxlili/wechat-finder-dlna

原理：微信投屏走标准 DLNA。电脑伪装成电视，投屏时会把真实 m3u8 送来。不抓包、不装证书、不代理。
后来工具也支持 AirPlay / Chromecast，我这边 DLNA 够用。

```bash
pip install wechat-finder-dlna
wechat-finder-dlna
wechat-finder-dlna --record live.mp4 --duration 01:00:00
```

第一次就会踩的坑：
- 手机和电脑必须同一局域网；AP 隔离、公司网组播过不去，列表里就没有设备
- 只能抓直播，不能抓回放
- m3u8 带签名会过期，直播重连 ffmpeg 可能退出，必须能看见文件还在不在涨
- 不要用 -re 实时读流，容易没声/花屏；用 `ffmpeg -i URL -c copy` 拷贝流，CPU 很低

## 为什么还要自己做 App

命令行能录，但撑不住四天多会场：
- 多条流就要多个终端，分不清 PID 对应哪场
- Mac 会休眠，所以要可选 caffeinate
- 终端是黑盒，不知道是在收流、卡住、还是已经退出
- 强杀 ffmpeg 可能导致 mp4 不完整，所以 Stop 和 Kill 必须分开
- 做 GUI 之前已经有命令行拉起的 ffmpeg，必须能 Attach by PID
- 关窗口不能把录制一起杀掉，任务列表要持久化，下次用 PID 再接回去

用 Xcode 搓了个 macOS 小工具：不重新发明拉流，只管理本机 ffmpeg。

## 产品功能对应的原因

新建任务：URL / 保存目录 / 文件名前缀 / 最长时长 / 是否 caffeinate。点 Add Recording 调本机 ffmpeg。
投屏拿地址 和 录制挂机 故意分成两步，失败模式不同，混在一个键里不好查。

卡片字段（状态、PID、路径、已写入大小、时长、速度、日志、上次刷新）都是被坑过才加的。
HLS 常见死法：进程还在，文件大小不动。有大小 + 刷新时间就不用猜。
速度长期远低于 1x 多半是网络/掉片；日志出现 403 就是地址过期，要重新投屏。

生命周期：
- Pause / Resume：暂停继续，PID 还在
- Stop：正常结束，尽量让 ffmpeg 写完尾信息
- Kill：强制结束，可能留下不完整文件
- Refresh：轮询，不要狂打磁盘

Attach by PID：收编外部已有 ffmpeg，尽量识别输出文件，轮询死活，允许发信号。

持久化：
- 退出不清空
- 下次恢复列表
- PID 还活着就继续监控
- 已结束任务留着直到手动清理
- App 是控制面，ffmpeg 是独立进程；重新 attach 时要核对还是不是 ffmpeg、路径对不对，避免误杀

## 结果

没有全自动。每次仍要：伪装电视 -> 手机投屏 -> 复制 m3u8 -> App 建任务。
省下的是后面几小时不用盯着。
后台跑、CPU 低、画质跟源站走。多任务能分开看。
关过 App 再回来，PID 还活着、文件还在涨。
没解决：地址过期不能自动重新投屏。接受它是录制管理器，不是视频号爬虫。

## 下一步（还没做）

语音转文本（长视频先按时间切）-> AI 按场次做结构化摘要 -> 只对关心的段落追问。
转写不塞进录制工具。录制是 IO/进程，转写是文件/模型。
